# `virtual_list.rs`

`VirtualList`: rows of one height for many thousands of items, rendering only those in view.

Read this before changing `src/virtual_list.rs`. When the module's behaviour changes, update this file in the same PR.

Cross-cutting design: [lists and selection](../design/lists-and-selection.md), [keyboard focus and navigation](../design/keyboard-focus.md), [scrolling](../design/scrolling.md).

## Details

`VirtualList { row_height }`: a list of rows of one height for many thousands of items that renders only those in view. Its node is as tall as all rows, so the `ScrollArea` around it (the nearest ancestor whose `overflow.y` scrolls, else the window) scrolls the whole list; under it is a pool of absolutely placed `VirtualListRow { list, shown: Option<ShownItem> }`s (`ShownItem { index, item }`: the item and its index exist together, `None` for a row that shows nothing; immutable, `ListItem`s): the rows in view, one for a part row and `OVERSCAN_ROWS` (2) beyond each edge. When `ScrollPosition` moves, `show_rows` (`PostUpdate`, before layout) hands rows on to the items now in view (item `i` goes to row `i % pool`, so a scroll by one row re-points one row); a row is never spawned or despawned for a scroll, and the pool only grows, when the view does. A row shows the text of an `Item<String>` in an `ItemLabel`, or with `List`'s `ItemViewCreator` the app fills it: the creator runs again, on the row emptied of its children, when the row is handed to another item (or the app observes the `VirtualListRow` insert). Selection is as for a `List` (`Selected` on the rows of selected items, a primary click or touch toggles as far as the selection allows; other pointer buttons pick nothing and the event goes on to bubble for an app's context menu, `only_a_primary_click_or_touch_picks_a_virtual_list_row`) but it is not a `ListBox`, whose observers would only see the pooled rows: it is one tab stop with its own keyboard observer (arrows move the active row, wrapping, Page Up / Page Down by the rows that fit in the view, stopping at the ends, a first Page Down with no active row landing on the first item as Arrow Down does, Home / End, Enter / Space toggle the active row as a click does, through `toggle_selected`, so one on a selected row deselects it as far as the selection allows and a `One` keeps its item (`enter_or_space_on_a_selected_virtual_list_row_deselects_it_as_far_as_the_selection_allows`); each scrolls the active row into view by setting the area's `ScrollPosition`), and `ActiveDescendant` names the row of the active item while it is in the pool; `show_rows` treats a source that does not resolve (a despawned selection behind a `Selection::Ref`) as empty, so the rows empty out and the height drops (`a_virtual_list_is_cleared_when_the_source_behind_its_selection_is_despawned`); it runs before `focus.rs`'s crate-private `DrawFocusRing` set, so the focus ring is on the row the frame it moves, and `activate_on_focus` runs before it as a system that reads `InputFocus` (set in `PreUpdate`), not as an observer of `FocusGained`, which Bevy sends after the layout, so a list focused by Tab or a click names and rings its active row the same frame (`virtual_list_keyboard_pages.ron`). A `Role::ListBox` whose `size_of_set` is the number of items, each shown row a list item with `position_in_set` (its item's index plus one) and the same `size_of_set`, kept by `sync_accessibility` in `AccessibilitySync`, so a pooled row reads as item 5,001 of 10,000. `RowHeight::new(f32)` returns a validated `RowHeight` or `RowHeightError`: the height must be finite and at least `MIN_ROW_HEIGHT` (10 px), which bounds the pool even at the smallest accepted height; `VirtualList::new(RowHeight)` takes that value, and `VirtualList::separated(RowHeight)` returns an error unless it is above the 22 px of vertical padding and ring. The list fields are private, so callers cannot invalidate a live height; construction errors are covered by `invalid_virtual_list_row_heights_are_rejected_and_the_minimum_keeps_the_pool_bounded` and `separated_virtual_list_rejects_a_row_height_at_or_below_its_chrome`. `List` is untouched. `VirtualList::separated(row_height)` (the `separated` field) gives the rows the look of a `CornerStyle::Separated` `List`: 6 px in from the list's edges, 2 px gaps, rows rounded at the control radius with the separated item padding and a 1 px border that is the `selection_ring` on the selected row, which also gets `hovered_selected_item`. It uses `list.rs`'s own constants, `item_background` and `item_border`, so the two cannot drift, and the rows stay absolutely placed: row `i` is at `6 + i * (row_height + 2)`, the node is `2 * 6 + n * (row_height + 2) - 2` high, and the pool, `show_rows`, Page Up / Page Down (`rows_per_page`), `scroll_into_view` in `navigate` and the scroll limit all use that pitch (`VirtualList::pitch` / `row_top` / `content_height`); `position_in_set` is by index, so the gap does not touch it. `row_height` is then the whole row, padding and ring included (above 22 px). Still only pooled rows are styled each frame (`virtual_list_separated_ring_follows_selection.ron`, `virtual_list_separated_keyboard_pages.ron` on the `SeparatedVirtualList` screen)
