# `select.rs`

The selection model: `Selection`, `SelectionValue`, items (`Item<T>`, `ItemOf`, `ItemsRef`), `ItemsChanged`, and the shared helpers that reconcile views with items.

Read this before changing `src/select.rs`. When the module's behavior changes, update this file in the same PR.

Cross-cutting design: [lists and selection](../design/lists-and-selection.md).

## Details

the selection model: `Selection` (`Value` or `Ref`), `SelectionValue` (`One` / `ZeroOrOne` / `OneOrMore` / `ZeroOrMore`), with two documented pending states, `One(Entity::PLACEHOLDER)` and an empty `OneOrMore` (`SelectionValue::is_pending`): a pending selection has no selected items (`iter()` yields nothing, `len()` is 0, `is_empty()` is true, `single()` and `last()` are `None`, `is_selected(PLACEHOLDER)` is false), so widgets treat it as empty without checks of their own; it keeps its cardinality, the first item repairs it through `ItemsChanged` (`repair_pending_selections`, no polling) and the update methods never clear an initialized `One` / `OneOrMore` back to pending; the `Selection::builder()`, `Item<T>`, `ItemOf` / `ItemValues` / `ItemsRef`, `ItemsChanged`, and the `SelectionParam` / `ItemParam` system params; the crate-private `StructureChanges::<Widget, T>` system param for a system that builds a child per item (`FilterChips`, `Gallery`, `Toolbar`): `affected()` names the widgets to look at in this frame and nothing else, so a change to one source does not make every widget compare its items. A widget is affected when it changed, when its root selection entity (after one `Selection::Ref` hop) or its items entity (`ItemsRef` or its own) had a changed `Selection`, `ItemValues` (also removed, when the last item went), `Item<T>` or `ItemOf`, an `Item<T>` was removed from an item of that source, or its own `ItemsRef` was replaced; widgets sharing a source are all named, an unrelated one never is, and a quiet frame does no work (`a_change_to_one_chips_source_leaves_independent_chips_alone`, `chips_sharing_a_selection_or_items_are_all_rebuilt_by_a_change_to_the_source`, `replacing_the_items_ref_moves_the_chips_to_the_new_source_and_removals_are_seen`, `a_pending_selection_is_repaired_when_its_items_arrive_and_the_chips_follow`; `SelectionParam::sources_of` resolves a widget's two entities, and none when its `ItemsRef` points at an entity that is gone (Bevy drops that `ItemsRef` a moment later; `refresh_selection_items`, started by `Discard<ItemsRef>` for a replaced one and `Add<ItemsRef>` for a new one, also inserts again the selections of the widgets that refer to the refreshed selection (`Selection::Ref`) and the selection itself when it has no `ItemsRef`, so they look the source up anew, clear their views and draw a later live source; `a_list_over_items_that_are_gone_shows_nothing_and_recovers` and its seven siblings for `FilterChips`, `Toolbar`, `Gallery`, `ColorPalette`, `SegmentedControl`, `TabBar` and `VirtualList`, #785); `SelectionParam::get_items` returns the items of a widget's source as a slice, empty for an existing source with no `ItemValues` yet (`get_item_values` is `None` there), which `List`, `VirtualList`, `SegmentedControl`, `TabBar`, `Toolbar`, `Gallery`, `FilterChips` and `ColorPalette` use, so replacing `ItemsRef` with such a source detaches the old observer, clears the views and the active row, and the source's first item appears later (`switching_to_a_source_without_items_clears_the_views_and_follows_its_first_item`, #695). the crate-private `unwatch_dangling_items(widgets, selections, commands, clear)` is the shared clearing step of `SegmentedControl` and `TabBar` for a despawned source (see their rows): for each widget with an `ItemsObserver` whose `SelectionParam::get_items` is `None` it drops the record (so a later `Selection` insert watches again) and runs the widget's own clear; `items_change` also triggers `ItemsChanged` with no items for a live entity that loses its last `ItemValues` (`RemovedComponents`), so widgets drawn from it clear instead of keeping stale views; a despawned source is not reported (its observers go with it). Covered per widget by `a_filter_chips_row_`, `a_toolbar_`, `a_gallery_` and `a_color_palette_clears_and_refills_as_its_source_is_replaced_emptied_and_restored`, `a_dormant_palette_woken_over_an_empty_source_has_no_swatches_until_its_first_item` and `a_list_drops_selected_from_its_views_when_cleared_and_gives_a_one_selection_its_first_item`; a `ColorPaletteCombo` re-watches its palette when the combo's `ItemsRef` is replaced; the `filter-chips-one-changing` bench workload measures it); **a despawned source** takes the entities holding its `ItemsRef` with it, so a widget whose `Selection::Ref` pointed at one of them is left with a reference that resolves to nothing and no observer: `StructureChanges::affected` also names a widget whose `Selection::Ref` dangles (`SelectionParam::is_dangling`) when any `Selection` was removed, and `List` / `ColorPalette` run `clear_dangling_lists` / `clear_dangling_palettes` (`list.rs`'s `unwatch_dangling`: drop the `ItemsWatch` observer and rebuild from no items), so the views clear as for a source with no items, `find` logs its `error!`, and inserting a new `Selection` that resolves brings the views back (`a_list_is_cleared_when_the_source_behind_its_selection_is_despawned` and the same for `FilterChips`, `Toolbar`, `Gallery`, `ColorPalette`; #752; `SegmentedControl`, `TabBar` and `VirtualList` do not handle it yet); `ItemsChanged::items` is one `Arc<[Entity]>` snapshot taken when the change is detected and shared by every observer (cloning the `Arc` copies no entities; `every_observer_of_one_change_shares_one_snapshot_of_the_items`, `a_snapshot_is_not_changed_by_a_later_mutation_of_the_items`; `items-shared-adding` bench workload, #681); the crate-private `plan_views(existing, wanted)` (matches existing views to wanted keys, returning a `ViewPlan` of reusable entities per slot and stale ones; the first view per key is kept) and `order_views(children, is_view, views, stale)` (the new children order, `None` when it is already right; the app's children keep their place) used by `FilterChips`, `Toolbar` and `Gallery` to reconcile instead of rebuilding (#690), and the crate-private `items_in_order(children, items, item_of)` (children in item order, the first child per item, then the children that show no item, the app's, in their order; shared by `order_tabs` and `order_segments`, linear) and the crate-private `watch_items` / `ItemsObserver` put one `ItemsChanged` observer on a values entity per widget (`SegmentedControl`, `TabBar`), recorded on the widget so it is despawned with it, also when the record is replaced (two `watch_items` calls before the first one's commands apply leave one observer), and with the values entity, never in a `Local` map; a `one()` / `one_or_more()` selection with no item yet waits in the private `SelectionResource::pending` and is repaired by an observer of `ItemsChanged` for its items entity (nothing polls it), and dropped by an observer of `Remove<Selection>`, so a despawned selection leaves no entry; ownership: `Item<T>::data` is public and app-owned (edit it in place, widgets observe the change), `ItemOf(pub Entity)` is Bevy's relationship input (insert it again to move an item, the `ItemValues` of the old and new owner follow; `ItemValues` has no mutable access), `ItemsRef(pub Entity)` is immutable (replace it, never edit it): an observer of `Discard<ItemsRef>` queues `refresh_selection_items`, which drops selected items that are not the new source's, gives a `One` / `OneOrMore` the new first item (pending, and repaired by `ItemsChanged`, when the source has none yet; the widgets draw it once its first items arrive, a source with no `ItemValues` having nothing to redraw from) and inserts the `Selection` again so the widgets redraw (`replacing_items_ref_refreshes_the_selection_and_the_widget`); the pending list holds one entry per selection; **order is significant** for `OneOrMore` / `ZeroOrMore`: `iter()` yields selection order, `trim_to_length` keeps the first items, and `set_selection` compares the items in order, so the same items in another order replace the selection (the way to reorder; `BreadCrumbs` follows) and only the same items in the same order give `None` (`bread_crumbs_follow_a_reordered_selection_and_trim_from_the_new_order`)
