# `filter_chips.rs`

`FilterChips`: a wrapping row of pill chips that picks one `Item<Chip>`.

Read this before changing `src/filter_chips.rs`. When the module's behaviour changes, update this file in the same PR.

Cross-cutting design: [keyboard focus and navigation](../design/keyboard-focus.md), [lists and selection](../design/lists-and-selection.md).

## Details

`FilterChips` over a `One` `Selection` (own or `Selection::Ref`) of `Item<Chip>` (`Chip { label, count: Option<usize> }`): a wrapping row (6 px gap) of 30 px pill `ChipView`s, each a `Button` that picks its item on `Activate`, the row one tab stop with arrow keys (a `RovingGroup`); the active chip is filled with `chip_on` / `chip_on_ink`, the others outlined in `chip_border` with `text_secondary` text (`text_primary` on hover) and the count at 0.6 alpha. Changing the `Chip` in an `Item` updates its chip's text in place; adding, removing or reordering items reconciles the chips by item (`select.rs`'s `plan_views` / `order_views`): a chip whose item stays keeps its entity, focus and hover, only missing chips are spawned and stale ones despawned, and the row is reordered once only when the order differs (`a_structural_change_to_chips_keeps_the_views_and_the_focus_of_the_items_that_stay`; `filter-chips-editing` bench workload, #690). The respawn check (`sync_chips`) looks only at the widgets `select.rs`'s crate-private `StructureChanges::affected` names, so a frame without a change, or a change to another widget's source, builds no `Vec` of the items (`filter_chips_do_not_look_at_their_chips_in_a_frame_without_a_change`). Text size is `Theme::font_size_chip`. Styled by `theme_chips` (new chip, `Theme` change, hover, selection or item change), not every frame; `restyle_changed_chips` restyles only the chips of rows whose own or referenced `Selection` changed, the hovered chips and the chips of a changed `Item<Chip>`, never every chip, and a hover or item edit is handled in a frame where a selection changed too (`filter_chips_restyle_only_the_rows_whose_selection_changed`, `a_hover_and_an_item_edit_are_restyled_in_a_frame_where_a_selection_changed`; `filter-chips-selection-changing` bench workload, #709), and the chip's `TextFont` is written only when it differs (`set_if_neq`): a write marks the font changed and makes Bevy lay the whole tree out again, 24 ms a frame more in a 500-row tree, `filter-chips-restyling` (`restyling_filter_chips_with_an_unchanged_font_writes_no_text_font`, `hovering_a_filter_chip_writes_no_text_font`, `restyling_filter_chips_with_a_changed_font_still_writes_it`; `filter-chips-restyling` bench workload, #710); the arrows move between chips and pick (see [composite widgets](../design/keyboard-focus.md#composite-widgets-are-one-tab-stop-with-arrow-keys)). To a screen reader the row is a `Role::RadioGroup` and each chip a `Role::RadioButton` labelled with its label and count (`Waiting 3`), toggled while active (`filter_chips_accessible_radio_group.ron`)
