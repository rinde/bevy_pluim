# `stack.rs`

`Stack`: shows the one `StackItem` child that matches a selection, building children lazily.

Read this before changing `src/stack.rs`. When the module's behaviour changes, update this file in the same PR.

Cross-cutting design: [lists and selection](../design/lists-and-selection.md).

## Details

`Stack { selection_ref }` shows the one `StackItem` child matching the selection; a `StackItem` is either a creator (`StackItem::new`, optionally with an id through `new_with_reference`) or a reference to another item's creator by id (`new_reference`), a private enum behind the read-only `creator()` and `reference_id()` accessors (the fields are not public) with no child entity stored on it: the children a stack has made are cached per stack, in a private `StackChildren` component that `Stack` requires, keyed by the item whose creator made the child, so two stacks sharing a selection and items each build and show a child of their own and a despawned stack takes its cache with it (a cached child counts only while it is still a child of that stack; `update_stack_item` prunes the others when a new child is recorded; a reference resolves to the creator item by id and reuses that stack's child of it, never another stack's; `two_stacks_sharing_a_selection_each_get_a_child_of_their_own`, `two_stacks_sharing_a_selection_each_build_their_own_scene_child`, `despawning_a_stack_leaves_the_other_one_and_a_recreated_stack_gets_new_children`); a selected reference with no item that has its id logs an `error!` and hides the current child; a pending selection shows nothing; `StackChildCreator` is the public `SystemId` of a creator, and `StackChildSpawner` (`parent` the stack, `creator_item` the item whose creator runs) records the id of the entity it spawned in that stack's cache; children are created lazily by a registered system (`StackChildSpawner`, whose `spawn` takes a bundle and `spawn_scene` a scene, the stack child being the scene's root) and hidden, not despawned, when deselected; one global observer of `Insert<Selection>` switches every live `Stack` whose `selection_ref` is that entity or holds a `Selection::Ref` to it (one hop, so a stack over a reference follows the selection it refers to: `a_stack_over_a_selection_ref_follows_the_selection_it_refers_to`), so a despawned stack reacts to nothing; `Stack` is immutable (`#[component(immutable)]`, `Stack { selection_ref }` and its `FromTemplate` unchanged, a `compile_fail` doctest guards `&mut Stack`): inserting a new one on a live stack (an observer of `Insert<Stack>`) shows the child of the new selection, hides the children of the former source (kept, shown again if the stack points back) and hides all when the new entity has no selection, and the former source no longer switches it (`replacing_a_live_stacks_selection_ref_shows_the_new_selection_and_ignores_the_old`); `spawn` gives the child a default `Node` after spawning it and `spawn_scene` on the scene's `Ready` (bevy applies queued scenes later), in both only when it has none after its own required components, so a `Panel`'s width is kept
