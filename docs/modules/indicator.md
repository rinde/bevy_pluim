# `indicator.rs`

Crate-private sliding highlight behind the selected item of a track (segmented control, tab bar, light-dark toggle).

Read this before changing `src/indicator.rs`. When the module's behavior changes, update this file in the same PR.

## Details

a crate-private module: the sliding highlight behind the selected item of a track, shared by `SegmentedControl`, `TabBar` and `LightDarkToggle`. The `Indicator` trait (`of(owner)`, `owner()`, `color(theme)`, `segmented_selected` by default), the generic systems `spawn::<I, Track>` (gives a track without one its indicator, looking only at candidates: the tracks whose component changed (`Changed<T>`, a new track included) or, once any indicator of that kind was removed (`RemovedComponents<I>`), every track; a track has one when a child of its own is an indicator that names it as owner, never a scan of all indicators, so an idle scene costs nothing and a re-inserted or despawned indicator leaves exactly one; an indicator reparented away from its track without being removed is a stray that the next pass puts back under the track it names (strays found by owner once per pass, only when a candidate lacks a child indicator; `an_indicator_reparented_away_from_its_track_is_taken_back_not_doubled`, #730) (`every_track_has_exactly_one_indicator_after_reinsertions`, `a_removed_indicator_is_made_again_once_and_other_tracks_keep_theirs`; the `indicators-animating` and `indicators-removed` bench workloads), a child absolutely placed behind the items with `ZIndex(-1)`, `Pickable::IGNORE`, hidden until placed) and `animate::<I, Track, Item>` (slides it to the laid-out box of the track's `Selected` item with an exponential ease, `INDICATOR_RATE` 18 per second, snapping at the first placement and under `INDICATOR_SNAP` 0.5 px, hiding it with no selected item; **the slide is drawn by `UiTransform`, not `Node`** (#768): the indicator's `Node` `left` / `top` / `width` / `height` hold the goal, the laid-out box of the selected item, and are written only when that box moves by `GOAL_EPSILON` (0.01 px) or more, while the `UiTransform` translation (the visible center's offset from the goal's) and scale (visible size over goal size) ease to zero and one, so a frame of sliding writes no `Node` and dirties no layout; when the goal moves, the transform is recomputed so what is seen stays where it was; the `UiTransform` is written only when it changes; `UiGlobalTransform` includes it, so a scenario reads the drawn position from it or the drawn left from `UiTransform.translation.x.0`, never `Node.left` alone; the scale slightly stretches the corner radius mid-slide; `a_sliding_indicator_moves_by_transform_and_leaves_its_node_alone`). `animate` also resets the `UiTransform` to rest when the indicator hides with no selected item (`an_indicator_hidden_mid_slide_has_its_transform_back_at_rest`). `SegmentedControl`'s restyle (`style_control`, `style_segment`, `style_indicator`) writes a `Node` only when it differs (`set_if_neq`): any `Node` write, equal or not, makes taffy dirty layout up to the root, and every selection change restyles its control (#782; `reinserting_a_segmented_controls_selection_does_not_change_any_node`; `TabBar` and `LightDarkToggle` do not yet). The `bevy-nodes-resizing` bench workload is the plain-Bevy baseline of `indicators-animating`. Each widget has its own indicator component (`SegmentIndicator`, public; `TabIndicator` named `TabIndicator`, `OptionIndicator` named `OptionIndicator`, crate-private), registers the two systems, and makes its items transparent (`Color::NONE`) so the indicator is the selected look; the text and icon colors still follow the state at once (`a_tab_bar_slides_its_indicator_to_a_newly_selected_tab`, `a_light_dark_toggle_slides_its_indicator_to_a_newly_chosen_option`, `a_segmented_control_slides_its_indicator_to_a_newly_selected_segment`)
