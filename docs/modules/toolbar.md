# `toolbar.rs`

`Toolbar`: a row of tool buttons over `Item<Tool>`, filled or underlined.

Read this before changing `src/toolbar.rs`. When the module's behaviour changes, update this file in the same PR.

Cross-cutting design: [keyboard focus and navigation](../design/keyboard-focus.md), [lists and selection](../design/lists-and-selection.md).

## Details

`Toolbar { style }` over a `Selection` (own or `Selection::Ref`) of `Item<Tool>` (`Tool { icon, label, group, key_hint, tone }`): a row of `ToolbarButton`s (`Button`s; the toolbar is one tab stop, left / right / Home / End move the focus only, a `RovingGroup`) that pick their item on `Activate` with `toggle_selected`, so a `One` toolbar keeps its tool and a `ZeroOrOne` one clears when the open one is activated; a vertical `Divider` goes between neighbouring tools of different `group`. `ToolbarStyle::Filled` is 66 x 60 px with a label under a 22 px icon, the active button filled with `accent` and `AccentText` ink; `Underlined` is 44 px icon-only, the active one `accent_subtle` with an `AccentSubtleText` icon and an `accent_subtle_bar` bar. A tool's `tone` (`Tool::with_tone`) recolours it: `Danger` turns icon and label `danger_hover_text` when hovered and fills the active button with `danger` and `DangerText` (a bulldoze tool); `Warning` shows `WarningText` on `warning_background` when hovered or active. The tool's label is the `AccessibilityNode` label in both. `ToolbarLabels` (`Shown` default, `Hidden`; immutable, required by `Toolbar`) hides the labels of a `Filled` toolbar: the label gets `Display::None` and the buttons shrink to 56 x 52 px, without respawning; `Underlined` is unaffected. Changing the items or their groups reconciles the buttons and dividers by key (`Slot`: item and hint, or divider; `plan_views`): kept buttons keep their entity and focus, dividers are regrouped, and a style change respawns the buttons (`a_structural_change_to_a_toolbar_keeps_its_buttons_and_regroups_the_dividers`; `toolbar-editing` bench workload, #690); changing a `Tool` updates in place. `sync_buttons` looks only at the widgets `StructureChanges::affected` names (`a_toolbar_does_not_look_at_its_buttons_in_a_frame_without_a_change`); `update_buttons` and `sync_tooltips` still visit the buttons each frame. A tool with a `key_hint` (`Tool::with_key_hint("1")`) gets an absolutely placed hint text (10 px semibold, 5 px from the top, 7 px from the right) in the button's ink at 60 % opacity, so it follows the active state; the library only shows it, the app binds the key. To a screen reader the toolbar is a `Role::Toolbar`; its buttons stay `Role::Button`, `toggled` true while their tool is active and false otherwise. A `ToolbarButton` has private fields (`item()`, `owner()`) and only the widget builds it; it has no style of its own, the style is its toolbar's, and `sync_buttons` respawns the buttons when the `ToolbarButtonRefs` variant no longer matches `Toolbar::style`. `ToolbarButtonRefs` is an enum, `Filled { icon, label, hint }` or `Underlined { icon, bar, hint }` (`hint` only for a tool with a `key_hint`), with accessors `icon()`, `label()`, `bar()`, `hint()` and `style()` (`toolbar_buttons_always_have_the_children_of_their_toolbars_style`). The buttons of an underlined toolbar get a `Tooltip` with their tool's label from `sync_tooltips`. A widget only touches a tooltip it added itself, marked with the crate-private `OwnedTooltip(text)` of `tooltip.rs` (shared with `SegmentedControl`): a `Tooltip` with other text, put on by the app, is kept, and the widget's own is removed again when the button no longer needs it (a toolbar not underlined). Limit: an app `Tooltip` with exactly the tool's label, put on before the widget's, is not told apart from it

Touch: a tap picks as a click does, a finger that slides off before lifting picks nothing, and no hover look stays after the lift (a finger never hovers); the focus, and so the roving stop, follows the tapped item (`toolbar_touch.ron`).
