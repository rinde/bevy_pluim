# `numeric_stepper.rs`

`NumericStepper` and its validated `Value`: - / + buttons, arrow keys, drag to scrub, click or F2 to type.

Read this before changing `src/numeric_stepper.rs`. When the module's behavior changes, update this file in the same PR.

Cross-cutting design: [keyboard focus and navigation](../design/keyboard-focus.md), [pointer, touch and buttons](../design/pointer-and-buttons.md).

## Details

`NumericStepper`, its `Value`, `UIntValue<T>`, `FloatValue`, `ValueError`, `ValueChange`; `Value::new_u8` / `new_u16` / `new_u32` / `new_f32` return `Result<Value, ValueError>`: a minimum above the maximum, a zero integer step, a non-finite float initial value or bound and a non-finite or non-positive float step are rejected as given (bounds are never swapped, a step never replaced), a valid initial value is clamped, equal bounds and a step larger than the range are valid (both buttons disabled). `Value::F32` holds a `FloatValue`, and `FloatValue` and `UIntValue<T>` have private fields with `value()` / `min()` / `max()` / `step()` getters and validated `new`; `Value` itself stays mutable but exposes no mutable field access. `increment` / `decrement` use checked integer arithmetic and leave a float unchanged when the result would overflow, cross a bound or not strictly change it (a rounding no-op), and `can_increment` / `can_decrement` agree. To change a float's bounds build a new `FloatValue` from the getters. `ValueRef` is an immutable Bevy relationship and `ValueReferrers` (public, reflected, read-only) is its target on the `Value`, listing the mirror steppers and the parts of every stepper showing it; `on_change` visits only the referrers of a `Changed<Value>` (plus a self-held stepper's own node) and writes label text, fill width and the spin button only when they differ, so an unrelated stepper costs nothing and a touched but equal value dirties no layout (`steppers-*` bench workloads, #663; `an_external_value_change_updates_only_the_steppers_that_show_that_value`). Prepared valid `Value`s are inserted in scenes with `~{value}`.

**Children:** the stepper owns only the parts it builds (the crate-private `StepperPart(stepper)` marks the track, buttons and label) and an open `ScrubEditor`; inserting a `NumericStepper` again, or for the first time on an entity that already has children, replaces just those and keeps the app's children, with the parts added after them (`inserting_a_numeric_stepper_keeps_app_children_at_first_and_every_later_insert`). Replacing a stepper while its number editor is open and focused despawns the editor, shows the new value label and leaves the arrow keys and F2 working (`reinserting_a_numeric_stepper_while_its_number_editor_is_open_keeps_app_children_and_leaves_no_stale_editor`). Its "-" and "+" are small `IconButton`s (accessible names `decrease_name` / `increase_name`, "Decrease" / "Increase" by default; icons `decrease_icon` / `increase_icon`, a drawn minus and plus when left at the default handle) that step on `Activate`; `format` (`fn(&Value) -> String`, default `Display`) says how the value is shown, in a label of at least `label_min_width` (`DEFAULT_LABEL_MIN_WIDTH_PX`, 54 px, defined in `slider.rs` and re-exported here, so the two widgets share one constant) so the buttons do not move; fields are read when the component is inserted, and one that cannot step (at the minimum or maximum, or a step short of it) gets `InteractionDisabled`; the arrow keys step it too (up / right increase, down / left decrease) through an observer of `FocusedInput<KeyboardInput>` on the stepper, which a focused button's keys bubble up to and which stops them there (pressed, repeated or released, also at a limit), so only the buttons are tab stops and an app's directional navigation never sees them. The stepper's own node is one spin button: an `AccessibilityNode` with `Role::SpinButton`, `numeric_value` / `min_numeric_value` / `max_numeric_value` / `numeric_value_step` from the `Value` (as `f64`), `value` the text `format` shows (kept in step by `on_change`, also for mirrors through `ValueRef`); `ValueChange` is triggered by the step itself (a button's `Activate` or an arrow key, only when the value moves), never by `on_change`, so spawning a stepper or the app setting its `Value` sends none (the display follows both); a stepper with no `Value` and no `ValueRef`, or a `ValueRef` whose target has no `Value`, logs an `error!` and is not built (no default `Value`) and `name: Option<String>` as its label (none by default); the value text is a plain `Text`, not a `Label`, so it has no node of its own.

**Scrubbing and typing (#623):** like a slider, the whole stepper can be dragged. A `ScrubTrack` child (the first child, absolutely placed behind the rest, `Pickable::IGNORE`, inset 30 px (`BUTTON_WIDTH_PX`) on the left and right so it spans the gap between the buttons) holds the `ScrubFill(stepper)` (`Pickable::IGNORE`, `slider_fill` at 25 % alpha, `theme_numeric_stepper` themes it), as wide as `Value::fraction()` (public, 0 to 1) of the track, kept by `on_change`: 0 % is the right edge of the "-" button and 100 % the left edge of the "+" button. The value label has `flex_grow: 1`, so the app can set the stepper's `Node::width` and the buttons stay at the ends. While a scrub drag is on, `on_mouse` sets Bevy's `OverrideCursor` to `ColResize` (cleared by `end_scrub`) and `HoverLock`, so the cursor is the resize one wherever the pointer is and nothing highlights; the "-" and "+" buttons carry the default `EntityCursor`, so hovering them does not change the cursor. A horizontal drag that starts anywhere on the stepper, the "-" and "+" buttons included, moves the value by `distance.x / width` of the range from where the press began, snapped to the step (`Value::set_fraction`, private) and sent as `ValueChange` only when it moves; it needs `DRAG_THRESHOLD` (3 px) first. The private `Scrub { start, dragged }` on the stepper keeps this; while `dragged` is set the buttons' `Activate` does not step (so a drag that ends over a button changes nothing more), and `end_scrub` (`Last`) clears it once the left mouse button is up and no touch is down (a press also resets it). Only the primary button (a touch counts) presses, drags and clicks: `MouseEvent` carries the `button` of the pointer event, and the stepper ignores the others (`a_primary_drag_scrubs_but_a_right_button_drag_does_not`, `scrubbing_a_mirror_stepper_changes_the_shared_value`, `the_scrub_fill_follows_the_value`) A click (not a drag) on the value text opens a number editor: the label gets `Display::None` and a `TextField` marked `ScrubEditor` (as wide as the label's minimum, named "Value", empty with the current value as its placeholder so typing replaces the value, focused by `focus_new_editors`) takes its place in the same child slot; Enter (or a press elsewhere, the field's commit) sets the value to the leading number of the text (`parse_number`; `Value::set_number` clamps to the bounds, rounds an integer and does not snap to the step; text with no number changes nothing), Escape leaves it. The editor is closed in `Last` (`EditorDone`, `finish_editors`) after the commit of the same focus loss was handled, and while it is open the stepper's arrow keys and pointer scrubbing leave it alone. Tests: `numeric_stepper_drag_scrubs.ron`, `numeric_stepper_type_number.ron`, the unit tests of `fraction`, `set_fraction`, `set_number` and `parse_number`.

**From the keyboard (#631):** F2 on a focused stepper (a key that bubbles up from a focused button; `on_key_input`, which stops it, ignores a repeat) opens the same editor through the shared `open_editor`, named "Value" for a screen reader like the pointer's. Enter is not the route: on the focused button it is that button's `Activate` and steps. The editor remembers the focused part (`ScrubEditor::restore_focus`) and `finish_editors` gives it the focus back when the editor closes with the focus unclaimed (Enter or Escape; a Tab or a click elsewhere keeps its own target). Test: `numeric_stepper_keyboard_editor.ron`.

**Cursors (#644):** the stepper carries Bevy's `EntityCursor` `ColResize` (a double arrow with a bar, for the scrub) and its value label, which now blocks the pointer from the stepper below it so only one cursor is hovered, and the open `ScrubEditor` carry `Text` (the I-beam, where a click edits); the buttons carry the default cursor (hovering them changes nothing) and a drag holds `ColResize` through `OverrideCursor`. `WidgetsPlugin::finish` adds picking's `CursorIconPlugin` unless the app has it, which copies the hovered `EntityCursor` to the window and sets the window's default cursor otherwise (`a_numeric_stepper_shows_a_resize_cursor_and_a_text_cursor_on_its_value`)

**Touch (#799):** a horizontal finger drag scrubs, a tap on "-" / "+" steps and a tap on the value opens the editor; a scrub that ends on a button does not step. `Scrub.pointer` is the pointer that went down: a second finger's press and drag are ignored. `end_scrub` releases `HoverLock` once no finger is down, on lift and on cancel. Scenarios: `numeric_stepper_touch_scrub.ron`, `_tap.ron`, `_second_finger.ron`, `_releases_hover_lock.ron`.

A tap elsewhere commits the open editor (#803, `numeric_stepper_touch_editor.ron`).
