# `filter_combo.rs`

`FilterCombo`: a `Combo` whose popup has a search box that filters the options.

Read this before changing `src/filter_combo.rs`. When the module's behaviour changes, update this file in the same PR.

Cross-cutting design: [popups](../design/popups.md), [keyboard focus and navigation](../design/keyboard-focus.md).

## Details

`FilterCombo` (`FilterCombo::default().with_name("City")`): an opt-in sibling of `Combo` (not a mode of it, so `Combo` is untouched) whose popup has a search box above the options. It is used like a `Combo` (a node with a `Selection`, own or `Selection::Ref`; a `ComboPlaceholder` while nothing is selected) and reuses `ComboButton`, `ComboList`, `ComboState` and `popup.rs`, plus `combo.rs`'s crate-private `chevron` / `selected_text` / `PLACEHOLDER_TEXT`. `FilterComboRefs` (private fields; getters `button()`, `popup()`, `field()`, `input()`, `list()`, `empty()`) is built by `finish_setup` once the search `TextField` has built its input. The popup is a `Float` card (`background_primary`, `border`) holding the search `TextField`, a `List` (`CornerStyle::Separated`, `Unreachable` so Tab never lands on it, `overflow.y` scroll with its own `ScrollPosition`, so the popup caps to the window like `Combo`'s via `place_open_popups`) and a `FilterEmpty` "No matching items" line (`Role::Status`, polite).

**The list is the full list**: its `Selection` is `Selection::reference` to the combo's, so rows are the original item entities, `Selected` and the items stay the list's own business, and the filter only sets `Node::display` on each `ItemView` (`Display::None` also takes a row out of Tab and the accessibility tree through `focus.rs`'s `is_hidden`); another widget on the same items is never filtered, and nothing replaces the `ItemsRef` (that could repair a mandatory selection). State is private: `FilterState { query, active, fresh, settle }` on the combo, a `FilterDirty` marker, and `ActiveOption` on the active row (its focus-ring `Outline`, drawn by `style_active_options` and re-coloured with the theme). A rename of a selected item also updates the button text (`selection_change`; `filter_combo_follows_a_rename.ron`, `renaming_an_item_updates_a_filter_combos_button_rows_and_matches`; the `FilterCombos` screen has a "Rename Delft" button, absolute and spawned last). The work is per change, never per idle frame: `mark_dirty` (list `Children` changed, or an `Item<String>` changed whose `ItemOf` owner is the items entity of an open combo's list, found with `SelectionParam::sources_of`, so a rename in an unrelated source rematches nothing and shared sources still do; `renaming_an_item_of_another_source_does_not_rematch_an_open_filter_combo`) and `on_field_change` (`TextFieldChange`) mark, `apply_filters` re-matches (case-insensitive substring of `Item<String>::data`, notes not searched, source order), keeps the active item if it still matches, else the first selected match on the first pass after opening (`fresh`), else the first match, else none. Opening (`on_state`, an observer of `Insert<ComboState>`) resets the query (a new `TextField` insert, which sends no change) and focuses the search input; closing moves the focus to the button only if it was on the input or list. Keyboard: the input has the keys (`on_key`, an observer on it, registered after Bevy's own `TextInput` observer, which runs first and queues a caret move for Up / Down that `on_key` pops): Arrow Down / Up move through the shown rows, wrapping, repeats included, and stop (`propagate(false)`, with Enter and Escape) so an app's directional navigation never sees them; Enter and numpad Enter (not repeats) toggle the active item through `SelectionParam::update_selection` on the list, exactly as a click, and close for a selection of one at most; Escape (by key code, since a source of key events may not fill in the logical key Bevy's input reads) closes without picking; nothing acts while `EditableText::is_composing()`. The search `TextField` input carries the crate-private `OwnKeys` marker so `text_field.rs`'s `on_key_input` leaves Enter and Escape alone. Focus: `on_focus_lost` closes when the focus leaves other than to the popup (a press in it gets the input back, a press on the button is left to its `Activate`, Shift+Tab to the button closes), `close_on_outside_click` closes on a release outside, and inside means the button, the popup's card, search box and empty line, and the list only for a selection of many. `keep_active_in_view` (`PostUpdate`, after layout, for `SETTLE_FRAMES` frames after a change) scrolls the list's own `ScrollPosition` to the active row plus the list padding and clamps it after the results shrink; it never scrolls a `ScrollArea` around the combo. To a screen reader the button is a `Role::ComboBox` (value the selection, `controls` the list, `expanded`) and the input a `Role::ComboBox` too (label `name` or "Search", value the query, `controls` the list, `expanded`, `active_descendant` the active row, also Bevy's `ActiveDescendant` for `App(Active(..))`); hidden rows, the closed popup and an empty-line that does not show are hidden nodes. Limits: a deleting key cannot be played by the scenarios (the tester's `Tap` carries no logical key, which Bevy's text input reads) and the headless tests have no font layout, so `backspace` there sets the text as a deleting edit would leave it (`FilterApp::backspace`); an IME's commit key is guarded only by `is_composing`.

**Touch (#803):** a tap on the button opens the popup with the focus in the search input, and a tap on an option picks and closes as a click does (`filter_combo_touch_types.ron`).
